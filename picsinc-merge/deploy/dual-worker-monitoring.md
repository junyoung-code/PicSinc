# Windows 주력·Mac 보조 워커와 텔레그램 알림

현재 진행·미정 사항은 [STATE](../STATE.md), 작업 처리 규칙은 [MASTER_SPEC](../MASTER_SPEC.md)를 따른다. 10팀 시험과 Windows 장시간 안정성 시험은 별도 후속 작업이다.

## 텔레그램 알림 설정

1. 텔레그램에서 공식 [`@BotFather`](https://t.me/BotFather)와 대화해 `/newbot`으로 PicSync 전용 봇을 만든다. 받은 토큰은 채팅이나 Git에 올리지 않는다. 이미 webhook이나 다른 감시 프로그램에 연결한 봇은 사용하지 않는다.
2. 새 봇의 대화창을 열고 `/start`를 보낸다.
3. Windows의 `picsinc-merge` 폴더에 Git 제외 파일 `.env.alerts`를 만들고 `TELEGRAM_BOT_TOKEN=<발급 토큰>` 한 줄을 넣는다. 파일은 전용 Windows 계정만 읽을 수 있게 둔다.
4. PowerShell에서 `node --env-file=.env.alerts scripts/telegram-chat-id.mjs`를 실행해 본인 채팅 ID를 확인한다. 여러 ID가 보이면 본인 대화를 확인한다. `.env.alerts`에 `TELEGRAM_CHAT_ID=<본인 ID>`를 추가한다.
5. `scripts/start-windows-alerts.cmd`를 실행한다. 봇에게 `/status`를 보내 **현재 현황** 응답이 오는지 확인한다. 응답이 없으면 `worker-logs/alerts-error.log`를 확인한다. 이 명령은 작업 처리 워커와 별개로 실행된다.
6. Windows 작업 스케줄러에서 위 `.cmd`를 **컴퓨터 시작 시** 별도 작업으로 등록한다. 전용 계정, 로그온 여부와 관계없이 실행, 동시 인스턴스 금지, 실패 시 재시작을 설정한다. 재부팅 후 `/status` 응답을 확인한다.

감시 프로그램은 서버의 인증된 상태 API에서 **대기·진행·최근 1시간 실패 건수**를 30초마다 읽는다. 평소에는 메시지를 보내지 않고, 본인 채팅에서 `/status`를 보냈을 때 최신 현황을 답한다. 대기 3건 이상 또는 최장 대기 60초 초과가 2분 지속되면 Mac 보조 워커 검토를 알리고, 정상화되면 복구를 알린다. 최근 실패 건수가 증가하거나 서버 상태 조회가 2분 이상 실패해도 알린다. 작업별 퍼센트나 어느 PC가 작업 중인지는 현재 API가 제공하지 않는다. 이 봇은 전용으로 사용하며 다른 `getUpdates` 소비자나 webhook을 함께 실행하지 않는다.

이 감시는 Windows PC에서 실행하므로 **PC 전원이나 인터넷이 끊기면 감시도 멈춘다**. Windows 자체의 오프라인 알림은 독립된 외부 감시가 별도로 필요하다. 또한 이 알림은 상태를 읽을 뿐 작업을 접수·변경하지 않는다. 로그는 `worker-logs/alerts.log`와 `alerts-error.log`에 남는다. `WORKER_TOKEN`과 봇 토큰은 비밀로 보관한다.

## 운영 체크리스트

- [ ] Windows 워커를 주력으로 켜고 실제 작업 1건이 완료되는지 확인한다.
- [ ] Mac에서 `node --env-file=.env.worker scripts/worker-status.mjs`를 실행해 `windows=online`을 확인한다. Mac을 켠 뒤에는 `mac=online`도 확인한다. 각 워커는 30초마다 신호를 보내며 90초가 지나면 `offline`으로 표시된다. 워커 코드 변경 후에는 두 PC에서 새 코드를 가져와 워커를 재시작해야 한다.
- [ ] 텔레그램 감시를 별도 작업으로 시작하고 `/status` 응답을 확인한다.
- [ ] 평소 Mac 워커는 끈다. 대기 증가 알림을 받고 Mac이 켜져 있고 네트워크가 가능할 때만 수동으로 켠다.
- [ ] 두 워커는 같은 서버 대기열에서 서로 다른 작업을 가져간다. Windows 우선권은 없으므로 Mac을 켠 동안에는 둘 다 작업을 받을 수 있다.
- [ ] 대기가 정상화되면 진행 중인 Mac 작업이 끝난 뒤 Mac 워커를 끈다. Mac을 계속 켜둘 필요는 없다.
- [ ] 출발 전 Windows 재부팅 후 워커·감시의 자동 시작과 텔레그램 수신을 확인한다.
- [ ] Windows 자체가 꺼졌을 때의 알림이 필요하면 독립된 외부 감시를 추가한다.

## 두 워커 동시 실행 시험 체크리스트

운영 사용자 작업을 방해하지 않는 분리 시험 환경에서 생성 사진으로 시험한다.

- [ ] Mac·Windows가 같은 시험 서버를 바라보고 서로 다른 로그를 남기는지 확인한다.
- [ ] 두 워커를 켜고 최소 2건을 동시에 접수해 각 워커가 서로 다른 작업을 가져가는지 확인한다.
- [ ] 각 작업이 한 번만 완료되고 결과가 중복 저장되지 않는지 확인한다.
- [ ] 한 워커를 작업 중 강제 종료해 할당 만료 후 다른 워커가 재처리하고, 오래된 완료 응답은 거절되는지 확인한다.
- [ ] 이때 대기·진행·실패 및 텔레그램 알림이 기대대로 변하는지 확인한다.
- [ ] 시험 후 Mac 워커를 끄고 Windows 단독 처리로 돌아온 것을 확인한다.
